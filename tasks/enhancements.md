## Product

- **Usage telemetry for the EBM signals** — `docs/user-paths.md` defines candidate signals per journey stage (time-to-first-review, % of reviewed posts edited within 14 days, cron vs. manual share, re-review rate, dashboard visits…) but nothing measures them; today's evidence is user #1's self-observation. Start locally and privacy-first: store counters/events in the plugin's own DB (no external calls), surface them on a small "Insights" box, so Current vs. Unrealized Value claims become evidence-based.
- **Yoast scores as SEO/Audit agent context** — user-approved 2026-07-23: append the numeric Yoast scores (already in the n8n payload) to the `Build SEO Body` and `Build Audit Body` user messages, framed as algorithmic signals, not ground truth. The Review agent stays Yoast-free by design (side-by-side decision, avoids score anchoring).
- **Yoast score snapshot per review** — store `{seo_score, readability_score}` from post meta into `result_data` at save-review time, so past reviews keep the Yoast standing they were compared against (the Post Reviews column shows live values only).
- **Full round-trip connection test** — the "Send test ping" button verifies WP → n8n (reachability + workflow active). It does not verify the reverse path (n8n → WP callback with the `X-PQM-Token`). A `ping` command that calls back to a dedicated endpoint would validate the whole loop, including the token.
- **Cron command choice** — `cron_command` is locked to `review`; allow scheduling other commands (audit, seo) once their result storage is on par.
- **Chat-provider contract doc** — document the webhook in/out JSON contract so any chat tool (Slack, kChat, Teams bot) can drive the workflow without reading the n8n nodes.
- **Wizard-style workflow builder** — pick commands/agents and assemble the workflow graph from blocks. Still deferred (KISS; config-injected export is the locked MVP approach). Note: a wizard-style *setup flow* (download → import → connect & test) now lives on the n8n Workflow page — this item is only about the graph builder.
- **Per-agent custom model IDs** — the Custom free-text model ID exists globally; per-agent overrides are limited to the curated registry. Add per-agent custom IDs only if a real need shows up (six extra text fields otherwise).
- **WordPress.org distribution** — readme.txt, screenshots, i18n completeness, GPL asset review. Deferred; GitHub Releases is the current channel.
- **Role-based access to plugin features** — user feedback 2026-09-22. Today every capability check is binary: `edit_posts` opens the dashboard, Post Reviews and every command trigger (REST `trigger-review` + `ajax_trigger_command`), `manage_options` opens n8n Workflow and Settings; Contributors therefore get the same command access as Editors. Target mapping on WordPress core roles: **Administrator** = full rights; **Editor** = everything an Author can do + per-agent overrides (model/effort) + Automated Reviews (cron) settings, no webhook/token/API-key config; **Author** = Review and Key Takeaways commands only, with a per-user action quota for cost control (e.g. N actions per month, configurable by the Admin, counter surfaced next to the buttons). Implementation notes: register plugin-specific capabilities (`pqm_run_basic_commands`, `pqm_run_all_commands`, `pqm_manage_agents`, `pqm_manage_cron`, `pqm_manage_connection`) on activation and map them to the three roles, so site owners can remap with any role editor; enforce in `PQM_Rest_API` permission callbacks and the AJAX handlers, not only in menu registration; the quota needs a small usage table or user meta keyed by month; the n8n callback path is unaffected (token auth). Decisions 2026-09-22 (ADR [0003](../docs/adr/0003-freemium-plan-and-role-based-access.md)): the Author quota is **per user**; **Contributors get no access at all** (no menu, no REST, no AJAX). Cron runs are site-level and outside the per-user quota; they count against the site-level cap of the plan item below, if one exists.
- **Free vs. paid plan (freemium)** — user feedback 2026-09-22. Free plugin = Review + Key Takeaways commands only; paid plan = all agents (Rewrite, Sources, SEO, Audit), per-agent overrides, Automated Reviews (cron), role management above. Shares the feature-gating layer with the role item: build one `PQM_Features::can( $feature )` gate that combines plan + capability so both items ship on the same code path. Decisions 2026-09-22: the paid plan is licensed **per site**; any plan-level usage cap is per site (contrast with the per-user Author quota above). Confirmed by the owner 2026-09-22, recorded in ADR [0003](../docs/adr/0003-freemium-plan-and-role-based-access.md): (a) **one zip, one build** — paid = a license key that flips the feature gate, no separate pro package to maintain; (b) **hosted licensing, not home-grown** — Freemius is the WordPress-native default (checkout, license validation, update delivery, WordPress.org-compliant freemium, at the cost of a revenue share and a sizeable SDK); keep the gate provider-agnostic (`PQM_Features` reads a single `is_pro()` source) so the provider can be swapped; (c) **free tier on WordPress.org later, not first** — the free tier's value is discovery, but WordPress.org must not block this work; ship free/paid via GitHub Releases first, then reuse the gating layer for the WordPress.org submission (their rules allow freemium as long as the free version is functional, which Review + Key Takeaways satisfies); (d) **one n8n template** — the plugin refuses gated commands before the webhook call, the template stays complete and the version handshake unchanged. Note the paid features still require the user's own Claude API key and n8n instance, so the price covers the plugin, not the inference cost.
