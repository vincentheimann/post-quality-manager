## Upgrading from an earlier version

These changes reach a site that ran an earlier version of Post Quality Manager without any prompt in WP Admin.

**The admin menu is now Post Quality.** It used to read "Content Quality". Its pages are the same: Dashboard, Post Reviews, n8n Workflow, Settings and Account. The Dashboard and Settings headings now read "Dashboard" and "Settings".

**Authors have a monthly limit.** Users without the "Run paid agents" right get 20 AI actions a month; 0 means no limit. Change it under Settings → Usage & Limits → Monthly Quota → AI Actions per User.

**Role rights stay as you set them.** Each right goes to its default roles once; what you change afterwards survives deactivation, reactivation and updates. Set them under Settings → Roles (Pro) or with a role editor plugin. The "View as" toolbar switch of the 3.0 and 3.1 test builds is gone; the Roles tab replaces it.

**Re-import your n8n workflow.** Send a test ping from the n8n Workflow page; when yours is older, it says so, names the version this plugin needs and offers Update workflow (a workflow the plugin manages) or Re-import the workflow. Until you update or re-import, an old workflow's trigger does not check that a call comes from your site, and a workflow imported before July 2026 still needs its WordPress user to hold "View reviews". The new import uses the Post Quality webhook credential (Header Auth with your webhook token), as the Workflow File section of the n8n Workflow page shows.

**A re-imported workflow has a new production URL.** Each site's workflow now listens on its own webhook path, so several sites can share one n8n instance. When the n8n Workflow page says "A re-import gives it a new production URL.", re-import the workflow, then copy the production URL from its Webhook Trigger and paste it as the n8n Webhook URL in Settings. Until you do, the plugin keeps calling your current workflow.

**Pro needs a license bought at postquality.com.** A key typed under Settings → License during the test builds no longer unlocks Pro, and the License Key field is gone. Buy Pro at https://postquality.com/pricing, install the Pro version you download after checkout and activate your key on the license screen it shows, or later with the "Activate License" link under the plugin on the Plugins screen (an Account page joins the plugin's menu once you opt in or activate a license). On activation, Post Quality asks whether to share your name, email address and site details with Freemius, the licensing service; skip it and the plugin works the same.

**The setup guide now continues past the first review.** After the first review it offers your Blog Profile, your Editorial Standards and scheduled reviews (Pro), one step each, every one skippable. A site set up earlier sees these three steps open; nothing changes until you save one, and skipping leaves your settings as they are. Until each is saved or skipped, the n8n Workflow page offers them under its status line ("Finish setting up: …"); once all are, the offer is gone.

**The setup guide now sets n8n up for you.** It connects your n8n with an n8n API key, asks once for your Anthropic API key and creates the workflow and its credentials in n8n itself; the key is passed on, never stored. The step-by-step manual setup now lives in the Workflow File section of the n8n Workflow page, where "Set up by hand instead" in the guide leads. A site whose workflow was set up by hand keeps that path: its guide shows one n8n step, Set up by hand, done.

**A test ping also checks your workflow's credentials.** With an n8n API key stored on the n8n Workflow page, each test ping also reads your workflow in n8n, without changing it. When a Claude node carries the webhook credential, or a node has no credential, the page says which nodes and how to fix them; fix them in n8n, publish the workflow, then press Test again.

**The plugin can take over a workflow you set up by hand.** With an n8n API key connected and your webhook URL saved, the n8n Instance section of the n8n Workflow page offers Let the plugin manage this workflow: it finds the workflow at your webhook URL and shows the credentials its nodes use, by name. Once you confirm, the plugin remembers that workflow and its credentials, and the setup guide shows its n8n steps done. Nothing in n8n changes.

**Rotate the webhook token in one click.** On a site whose workflow the plugin set up or manages, the n8n Instance section of the n8n Workflow page offers Rotate the webhook token: the plugin writes a new token into the webhook credential in n8n, saves it here and sends a test ping, so the old token stops working at once. A workflow set up by hand, without the plugin managing it, keeps its token; let the plugin manage that workflow to rotate it from here.

**Update the workflow in one click.** On a site whose workflow the plugin set up or manages, the n8n Workflow page now offers Update workflow when your workflow is older than this plugin needs: the plugin writes the newer template onto your workflow in n8n, keeps its credentials and its production URL, sends a test ping and shows the new version. No re-import, nothing to paste. A workflow set up by hand, without the plugin managing it, keeps the Re-import the workflow steps (and the paragraph above on its new production URL); let the plugin manage that workflow to update it from here.

**The n8n connection says when your API key stops working.** When the n8n API key stored on the n8n Workflow page is revoked or expires in n8n, the next Check again, Rotate token, Update workflow or test ping that reads your workflow notices it: the n8n connection section shows "n8n refused this API key" with the date and opens the key field, and Rotate token, Update workflow and the offer to manage your workflow wait until a new key passes. Rotate token and Update workflow refused that way say so at once, with the fix. A key whose permissions exclude creating credentials or publishing workflows is now named as such, with the way to make one that can. While the last test reports the webhook credential on your Claude nodes, Rotate token waits too, since a new token would stop them: fix the nodes in n8n, or press Update workflow, then test again.

**The menu shows the plugin's own icon.** The plugin's entry in the admin menu carries the Q-and-check mark instead of the generic chart icon; nothing else changes.

**Post Quality Manager now comes as a Free and a Pro build.** The Free version, the one WordPress.org will host, contains Review and Key Takeaways and nothing else: no Pro settings, and an n8n workflow without the Sources, SEO, Audit and Rewrite branches. Pro is the version you download after checkout and holds everything, as before. If a Pro site imported the Free workflow, the n8n Workflow page says so: download the workflow there and re-import it. To move from Free to Pro, upload the Pro version you downloaded after checkout as a new plugin and activate it; the Free copy is switched off for you, and your settings and reviews stay.

**The n8n Workflow page shows one next step.** The page now reads your site's state and leads with it: a status line ("Not connected to n8n yet.", "Your workflow answers. Version 6 · checked just now by a test.", or what needs attention), one button for the next step, and the rest — Set up by hand, the n8n connection, the Webhook — behind collapsed sections. The webhook URL is edited here now (step 4 of Set up by hand, or the Webhook section), with Save and test; Settings → Connection shows it read-only. Rotate token and Update workflow are buttons on this page, and the "What Each Agent Sends to Claude" table moved to Settings → AI, beside the values it reads. After the setup guide connects, sets up or hands over, the page behind it shows the new state without a reload.

**Uninstalling now revokes the Application Password made for n8n (Pro).** When the setup guide sets n8n up for you on a Pro site, it creates an Application Password on your profile for the WordPress credential in n8n; the setup guide now says so under the key field, and deleting the plugin revokes that password. A site set up before this version keeps its password: remove "Post Quality Manager (n8n)" by hand under Users → Profile → Application Passwords when you no longer need it. Also fixed in the same setup: two setups started at the same time no longer both create a workflow (the second is refused), an activation refused because another workflow already listens on this site's webhook path now names that cause and the two ways out, and the test ping right after the setup waits for n8n to publish the workflow instead of reporting a 404 at once.

**Start over on the n8n setup.** The n8n connection section of the n8n Workflow page offers Start over on a workflow the plugin set up or manages: it forgets that workflow and its credentials, the n8n Webhook URL and the last test here (your n8n API key stays), revokes the Application Password it made for n8n (Pro) and, when you tick the box, removes the workflow and its credentials in n8n too; the page then offers Set up n8n again. The plugin also remembers which n8n instance it set the workflow up on: connected to another instance, Update workflow and Rotate token stay off until you connect the first one again or start over, and nothing is sent to the new instance with the old ids. A test ping that meets a workflow deleted in n8n says so and points to Start over. Leftovers of a setup on another instance are no longer dropped silently: the setup guide and the setup's reply name that instance so you can remove them there by hand.

**Update workflow asks first on a workflow you made by hand.** On a workflow the plugin manages because you let it take over one you set up by hand, Update workflow now opens a dialog before anything is sent to n8n: it says the workflow's nodes are replaced, that its credentials, webhook path and name stay, and that every node, connection and setting you added by hand goes with the update (n8n keeps its own version history). Cancel leaves n8n untouched. A workflow the setup guide created updates in one click, as before. When the n8n Workflow page offers Update workflow for an older workflow or the Free variant, it now says the same: "The plugin can update it in place: the workflow's nodes are replaced; its credentials, webhook path and name stay."

**The test ping now proves the way back too.** A test of your n8n connection (Test again on the n8n Workflow page, the setup guide's Save and test and Set up the workflow, Rotate token, Update workflow) now has n8n call your site back, the way a review's result comes back, and waits a few seconds for that call: the page then says the round trip works. When the call does not arrive, the test does not pass and says what to check (n8n must reach your site's REST API; a local, private or password-protected site cannot be called back); when it arrives with a wrong token, the test names the node to fix in n8n. This needs workflow version 7: until you press Update workflow (a workflow the plugin manages) or re-import the workflow, the n8n Workflow page says your workflow is older than this plugin needs. An older workflow keeps working.

**Tell us what works and what broke, from the Dashboard.** A card at the bottom of the Dashboard opens an email to hello@postquality.com with your message and the facts a report needs (plugin and workflow versions, WordPress and PHP versions, the active theme's name) already filled in, or copies that text for you; nothing is sent unless you send the email yourself. Hide puts it away for you alone; Send feedback brings it back.

**The plugin's admin pages have new addresses.** They now live at `admin.php?page=postquality-dashboard`, `…postquality-posts`, `…postquality-workflow` and `…postquality-settings` (the Account page follows the menu); the menu entries are unchanged. A bookmark to an earlier address now shows WordPress's "not allowed" page: open the page from the menu and bookmark it again.

**Your settings, reviews, roles and schedule carry over to new names.** The first time this version loads, the plugin moves everything it stored (settings, the n8n connection, reviews, each user's monthly count, the role choices and the scheduled reviews) to new names starting with `postquality_`; the values do not change and there is nothing to do. A role editor plugin now lists the plugin's capabilities as `postquality_…` (for example `postquality_view_reviews`), and a role or user that held one keeps it under the new name. Deleting the plugin removes its data under both the old and the new names.

**No deactivation dialog on a site that skipped the usage-data choice.** The "why are you deactivating" form no longer opens on a site that skipped the usage-data choice at activation, and such a site sends nothing to Freemius when the plugin is deactivated or deleted. A site that shares usage data sees the form as before; one that no longer shares sees no form either and sends no earlier feedback answer when the plugin is deleted; what Freemius may still receive after an opt-out is in the privacy policy under Optional usage data.

**Pro asks for its license key, not for an opt-in.** On a site that ran the plugin before, activating the Pro version without a license showed "We made a few tweaks to the plugin, Opt in to make "Post Quality Manager" better!", although its link opened the license screen. While Pro waits for its license, that notice now reads "Pro is installed. Enter your license key to unlock it." followed by the link "Activate your license", which opens the same screen. Pro's notice goes on the next admin page once the license is activated, and the Free version's once the usage-data choice is made, including one left over from an earlier version. A notice an earlier test build stored keeps its words and its link (one stored before the admin pages got their new addresses answers "not allowed") until the plugin is deactivated and activated again, or the license is activated.

**Suggested text for your privacy policy.** Settings → Privacy → Policy Guide now holds a Post Quality Manager section: what the plugin sends to your n8n instance, the AI provider, your notification address and Freemius, and what it keeps on your site. Copy what applies into your own privacy policy; nothing changes on your site until you do.

**Your Notification URL now gets its report.** The plugin sends the Notification URL you set under Settings → Connection with each command, but the workflow lost it once it had saved the result to your site, so no report went out. Now each command posts its short report there after the save: the post's title and link with the result, or the error when the command could not complete. The report goes out even when your site refuses the save. This needs workflow version 8: until then the n8n Workflow page says "Your workflow is version 7; this plugin needs 11." with **Update workflow** (a workflow the plugin manages) or **Re-import the workflow**. An older workflow keeps working.

**Claude's current models, and Sonnet 5.5 as the default.** Settings → AI now lists Claude Opus 5.5, Sonnet 5.5 and Haiku 5.5 first, under Current models, with Opus 4.8, Sonnet 5, Sonnet 4.6 and Haiku 4.5 below under Earlier models. Claude Sonnet 5.5 is the new default model: a site that never saved its Settings runs its commands on it from this version. A site that saved its Settings keeps the model it saved; to switch, pick Claude Sonnet 5.5 under Settings → AI → Default Model and save. A site that typed one of the three new model IDs as its Custom model ID now gets that model's settings, with thinking turned off where the model allows it.

**Longer waits for Claude's answer.** Workflow version 9 gives Key Takeaways and Sources 60 seconds (was 30) and Audit and Rewrite 3 minutes (was 2) to get Claude's answer, and Sources, Audit and Rewrite more room for it, so a model that thinks before it answers (Claude Opus 5.5) and long posts are no longer cut off. This needs workflow version 9: until then the n8n Workflow page says "Your workflow is version 8; this plugin needs 11." with **Update workflow** (a workflow the plugin manages) or **Re-import the workflow**. An older workflow keeps working.

**Update workflow connects Rewrite on a site set up on the Free version (Pro).** A Pro site whose workflow was set up on the Free version, or taken over with Rewrite unwired, could not update its workflow: n8n refused every try, and "Try again in a moment" repeated it. **Update workflow** now creates the missing WordPress credential in n8n the way the setup does, with a new Application Password of the administrator who clicks, then updates the workflow with Rewrite connected. The n8n Workflow page says so beside the button, and the plugin revokes that password when the setup is removed. On a site without Application Passwords, the update goes through without that credential and Rewrite stays off, as the page already says; setting such a site up no longer stops at the workflow's activation either.

**A setup on a slow or fresh n8n cleans up after itself, and removing a workflow works on current n8n.** On an n8n installed minutes before, creating the workflow could take longer than the plugin waited, and n8n created it anyway: the setup said "Nothing was left in n8n.", and the next try added a second workflow of the same name. The plugin now waits up to 30 seconds for the workflow's creation; when n8n still does not answer, it looks the workflow up and removes it, or, when n8n has not made it yet, says so and removes it at the next try. Current n8n versions also refuse to delete a workflow for a moment after it is unpublished, so Start over (with the box ticked) and a failed setup left the workflow and its credentials in n8n; the plugin now tries the removal again for a few seconds, which is when n8n lets it go.

**A valid answer from Claude is no longer stored as invalid.** Claude sometimes adds a sentence after its answer, or writes its reasoning before it (the Audit agent's prompt allows that), and the workflow then stored "Sources Agent returned invalid JSON." or "Audit Agent returned invalid JSON." for a run that had worked (seen with Claude Sonnet 5.5, the default model). Workflow version 10 reads the answer with a closing sentence after it or reasoning before it, in all five agents: Review, Key Takeaways, Sources, SEO and Audit. This needs workflow version 10: until then the n8n Workflow page says "Your workflow is version 9; this plugin needs 11." with **Update workflow** (a workflow the plugin manages) or **Re-import the workflow**. An older workflow keeps working, but any of the five agents can still fail that way, Review and Key Takeaways on the Free version too.

**Post Quality Manager now needs PHP 8.1.** A site on PHP 8.0 keeps the version it has installed and gets no further updates. To get them, move the site to PHP 8.1 or later.

**A Post Quality box on the post edit screen.** Under the content of each post, in the block editor and in the Classic Editor, a Post Quality box now shows the post's latest review (score, status, date and top edits), runs Review on a published or pending post and links to the post's full review on Post Reviews. In the block editor, unsaved changes turn the button into Save and review, which saves the post first; in the Classic Editor, update the post first. Users who cannot view reviews do not see the box, and pages do not have it. On WordPress 7.1, while a box like this one is on the screen (an SEO plugin's box does the same), the block editor opens revisions on the classic Revisions screen instead of its visual revisions.

**Set up by hand imports the workflow from a file.** n8n 3 drops "Import from URL", so the import link has left the n8n Workflow page. Step 1 of Set up by hand now has you download the workflow and import the file from n8n's workflow menu: "Import", then "From file" (in n8n 3, "Import JSON"). It works the same on n8n 2. A link you copied earlier still works on n8n 2 for now.

**An answer from Claude without results is now stored as an error.** When Claude answered a command without the results it asks for (an empty object, or an object holding only an error), Key Takeaways and Audit stopped in n8n without reporting back: the post showed the command running until the page stopped waiting, and nothing was stored. Review, Sources and SEO stored a score Claude never gave. Workflow version 11 stores such an answer as an error for that post and command, for example "Review Agent returned no usable result. Run the command again.", and every command reports back to your site and to your Notification URL. A Review or Audit score with decimals, which your site refused while the post kept showing the command running, is now rounded to a whole number. A Review or Audit status other than the three your site shows (Ready to ship, Needs revision, Major revision) is stored as the same error, since your site could not save some of those statuses either. This needs workflow version 11: until then the n8n Workflow page says "Your workflow is version 10; this plugin needs 11." with **Update workflow** (a workflow the plugin manages) or **Re-import the workflow**. An older workflow keeps working, but such an answer still ends that way, for Review and Key Takeaways on the Free version too.
