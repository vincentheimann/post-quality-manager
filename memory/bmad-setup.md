BMad Method v6.13 (skills-based) is installed per project in `post-quality-manager\` since 2026-10-01 (ADR 0004); it replaced the hand-rolled `tasks/` process and closed the queued create-agentic-workspace conversion.

- **Skills** (`.claude\skills\bmad-*`, vendored copies via `npx skills add bmad-code-org/BMAD-METHOD -a claude-code --copy`, pinned in `skills-lock.json`): `bmad` (hub, setup, status), `bmad-build`, `bmad-spec`, `bmad-ticket`, `bmad-review`, `bmad-code-review`, `bmad-retrospective`, `bmad-project-context`, `bmad-customize`, `bmad-walkthrough` (added 2026-10-08 after its first use on entry 4.9), `bmad-ux` and `bmad-correct-course` (added 2026-10-12, ADR 0004 amendment), plus the module records `bmod-core-tools`, `bmod-method`. Deliberately not installed, with the reason for each in the ADR 0004 amendment: PRD / architecture / agent-persona skills, `bmad-build-auto`, party mode, brainstorming, brief / PRFAQ / forge-idea; `bmad-qa-generate-e2e-tests` is the candidate for later (pre-production check re-run).
- **Runtime** `_bmad\` (scripts, `config.toml`); **team overrides** `_bmad\custom\config.toml` (`active_initiative = "initiative-post-quality-manager"`), `_bmad\custom\bmad-build.toml` (persistent facts: `memory/lessons.md`, DoD, agnostic prompts, brand, never commit; `route_selection`: oneshot only ≤100 lines, ≤3 files, no schema/REST/template change; `activation_steps_append`: branch guard — halt on `main` — and "the user commits, never the agent", overriding the vendored steps' unconditional local commit), `_bmad\custom\ticketing-store-config.toml` (repo store; its `write` verb is edited to never commit, and its header says `active_initiative` belongs in the committed `config.toml`, not `config.user.toml`). `*.user.toml` are personal and gitignored. Since 2026-10-05 (ADR 0007, see [[agent-tooling]]) `bmad-build.toml` also loads `_bmad\custom\minimal-code-ladder.md` as a persistent fact and appends the `overbuild` thorough lens, and `_bmad\custom\bmad-code-review.toml` appends the same lens.
- **Ticket tree** `_bmad-output\`: `initiative-post-quality-manager\` (requirements UV1–UV7 from `docs/user-paths.md` + O1–O4 owner requests; epic envelopes `epic-freemium-and-roles`, `epic-ebm-telemetry`, `epic-yoast-context`, `epic-delivery-pipeline` in `tickets.toml`; parked items in Notes) and `backlog\` (standalone stories 1–6; stories 1 and 6 are the hitl manual passes of the 2026-07-24 UX work and of the 2026-07-22/23 pivots — both done 2026-10-07). Read with `uv run _bmad/method/scripts/tickets.py --project-root . status _bmad-output/backlog` (ready work) and `next` (empty until an epic is incepted); drop with `mark <folder> <id> dropped`.
- **Tree rules `tickets.py` enforces** (found 2026-10-26, when `status` had refused the backlog since story 2's second plan): one plan per leaf, joined by its `ticket:` field, so work that takes two builds is two leaves (stories 88 → 91), never two plans; the earlier extra build plans of stories 2, 78 and 86 carry `build_of:` instead, as records. Leaf types are `story`, `spike` and `bug` only: an enabler or chore is `type: story` (tickets 81, 87, 89 keep their `chore-` file names), otherwise `tickets.py` skips it and every `after` naming it fails.
- **Update**: ask the `bmad` skill to run `bmad setup` (it runs `npx skills update -p -y` and re-checks); never hand-edit vendored skill files or `_bmad\scripts`.
- **Prerequisites**: `uv` (0.11+) and Node 22 are installed on the owner's machine.
- **Managed context** since 2026-10-01: `AGENTS.md` is `bmad-project-context`'s managed block (provenance in the block header); refresh/audit/record go through that skill, never hand-edits inside the markers. `CLAUDE.md` holds only the Claude entry point: `@AGENTS.md`, session ritual, how work flows.
- **First dogfood complete 2026-10-01**: `/prioritize` ranked the freemium/roles epic first (Decision line in the initiative Notes), `bmad-spec` distilled ADR 0003 into `spec-freemium-and-roles/` and `bmad-ticket` incepted 8 stories; next step is `bmad-build` on story 1.1. The owner declined external policy sources (dbi services) — the managed AGENTS.md block carries repo-grown best practices only.
