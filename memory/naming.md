**Naming is decided (owner, 2026-10-08, backlog story 10).** The canonical rules are `docs/brand.md` § Naming; this file only points there and records what is not in the code yet.

- Full name **Post Quality Manager** (header, readme, README, repo); short form **Post Quality** (admin menu label, in-copy cross-references). "Content Quality" is retired as a name; since 2026-10-23 no admin string carries it (menu "Post Quality", headings "Dashboard" and "Settings", the not-connected message names "Post Quality → n8n Workflow"; a slice of story 41 pulled forward for story 86's screenshots).
- Slug and text domain `post-quality-manager` stay: checked free on WordPress.org 2026-10-08 (so is `post-quality`), auto-derived from the Plugin Name header at submission, permanent after approval. This unblocks `epic-delivery-pipeline` entry 4.6 (text domain / `languages/`).
- Tagline (readme short description, 124 chars, provider-neutral — no n8n, no model vendor, "AI" kept as discovery keyword): "Score every post, see what to fix next and keep your back-catalog sharp. AI content reviews, stored and tracked in WP Admin."
- Page headings name the screen only; "PQM" is code-only; no third-party trademark in name, slug, tagline or imagery.
- **Code prefix changes (owner, 2026-10-24):** WordPress.org asks for prefixes of four letters or more, so `pqm` / `PQM` becomes `postquality` / `PostQuality` / `POSTQUALITY` before entry 4.8, in two leaves (owner, 2026-10-26): backlog story 88 moved the code names, admin page slugs and script/style handles (no redirect from the old page addresses), then story 91 moves the stored names with a one-time upgrade. The `X-PQM-Token` header, the REST namespace `post-quality/v1`, the `WP_Error` codes in REST responses (`pqm_forbidden`, `pqm_feature_gated`…), CSS classes, DOM ids and `data-pqm-*`, element expandos (`el.pqmBusy`…), the per-site webhook path prefix `pqm-execute-`, the template's placeholders and node ids, the `metadata.pqmInsert` block marker in post content (owner, 2026-10-26) and the file names keep their names.
- **Story 88 built 2026-10-26:** one explicit rename table (classes `PostQuality_*`, the `includes/pqm-functions.php` helpers and `postquality_fs()`, the eight `POSTQUALITY_*` constants, the four hooks, the AJAX / admin-post actions and nonces, `postquality_settings_group`, the query args `postquality_setup` and `postquality_dismiss_cron_nudge`, the slugs `postquality-dashboard|posts|settings|workflow`, the handles `postquality-admin` / `postquality-app`, the JS globals `postqualityAdmin` / `postqualityCommandLabels`) applied as exact tokens over the plugin, `src/`, `tests/`, `bin/` and the current-truth records; ADRs, `_bmad-output/`, `CHANGELOG.md`, past release notes and `PORTFOLIO.md` stay as written. `tests/harness/prefix-harness.php` enumerates every defined-name category from the source (token_get_all + call literals) and fails on any name without the new prefix or with `pqm` in any case; its last row lists the stored literals that must stay until story 91 (edit that list there). The custom DOM events are `postquality:workflow-status|setup-closed|workflow-refresh|confirm-action`. The Freemius Account page moved with the menu slug (`admin.php?page=postquality-dashboard-account`; the SDK computes the menu slug at each load). One SDK fact (2.13.5 source, read 2026-10-26): `add_sticky_optin_admin_notice()` (`class-freemius.php` L7048–7068) stores its "Opt in" link, built from the menu slug, in the SDK's `admin_notices` storage once per site, so a site still holding that sticky notice from before the rename keeps a `page=pqm-dashboard` link in it until the notice is dismissed or the site opts in; story 91's upgrade may clear it. The i18n fixture `tests/i18n/post-quality-manager-de_DE-pqm-app.json` keeps its file name; a site check copies it under the handle's name (`tests/i18n/README.md`).
- Visuals: the WordPress.org asset set and the lockup artwork exist (2026-10-24, story 41) in `assets/` at the repository root (never in the zip): `banner-772x250.png` and `banner-1544x500.png` rendered from `assets/src/banner.html` by headless Edge, `screenshot-1..3.png` copied from the postquality.com captures, `lockup-b.svg` and `lockup-b-dark.svg` (Inter outlined, no `<text>`) by `uv run --no-cache --with fonttools python -I bin/outline-wordmark.py`; canon and re-render recipes in `docs/brand.md` § Imagery and the WordPress.org assets.
