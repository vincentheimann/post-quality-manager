**3.0.0 is the first release (2026-10-08), a pre-release test build:** tag `v3.0.0`, GitHub Release with `post-quality-manager-3.0.0.zip` (single root `post-quality-manager/`, `admin/build/` inside), published by `release.yml`. The owner merged release PR #64 before entries 4.2–4.7 and story 15, so 3.0.0 shipped without the version check, the template guard, Plugin Check, translation loading, release notes and the WP 6.6 install test of the zip. No external users had it at that point. Those stories continue and ship in the next release. CI (`.github/workflows/ci.yml`) lints and builds JS, runs the JS unit tests, lints PHP and runs the harness sweep on 8.1 and 8.3 (story 118, ADR 0018) and runs Plugin Check on the built plugin and on the Free build; `release.yml` (story 4.1, below) is the release path. **When CI runs (2026-10-15, plan `plan-ci-minutes.md`, after October's 2,000 included Actions minutes ran out and the $0 budget blocked every run until the minutes reset on 2026-10-30, a date corrected by the owner on 2026-10-28 from the 2026-11-01 first recorded):** every `pull_request` runs all four jobs; every code PR runs Plugin Check; `push` runs only on `main`, and there only the build and PHP jobs run (release-please PRs get no CI, so a release merge is guarded by the harness sweep only: version and Stable tag = Version; "Tested up to" is checked on the next code PR); a push to any other branch runs nothing; a change whose every path is in the `paths-ignore` list (tickets, `_bmad/`, `.claude/`, memory, ADRs, policies, release notes, `docs/user-paths.md`, `docs/distribution.md`, `n8n/`, `assets/`, AGENTS/CLAUDE/CONTRIBUTING/SECURITY/CHANGELOG) runs nothing, and `README.md` and `docs/brand.md` stay out of it because harnesses read them; a newer run on the same PR cancels the older one (concurrency group per PR number, cancelling only on `pull_request`); runs on `main` get their own group (`run_id`), so they are never cancelled and may run in parallel. In the `php` job a failed 8.1 step still runs the 8.3 lint and sweep (`!cancelled()`). Until the minutes reset, the local gates are the merge evidence, stated in each PR (owner, 2026-10-15).

- No empty `languages/` folder ships.

**How release-please finds the previous release (read 2026-10-29 in the source of release-please 17.6.0, the version `googleapis/release-please-action@v5` locks; for entry 4.8 on the fresh repository):** it first asks GitHub for Release objects (GraphQL, drafts included, only those whose tag version equals the manifest version). With none, it falls back to the repository's tags and looks for `v<manifest version>` (`include-component-in-tag: false` drops the component). The tag's commit is where the changelog walk on `main` stops; merged pull requests and the `autorelease: tagged` label play no part. Missing tag or a manifest that disagrees: no stop, and the whole history (under its 500-commit depth) lands in the changelog. `last-release-sha` always stops the walk and `bootstrap-sha` only when no release was found, both compared with the full 40-character id (a short one never matches). `release-as` forces the version but opens no release PR without a releasable commit since the last release. The changelog is prepended above the last version heading and released sections are never rewritten. Today's `release.yml` publishes the release (L101) before its Freemius step (L124), and a re-run appends the release notes to the body again (L111); entry 4.8's Notes hold the proposed order.
