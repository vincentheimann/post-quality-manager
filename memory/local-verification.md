**An agent can check the plugin on a real WordPress itself, headlessly (backlog story 9, tooling built 2026-10-26).** The how is [`docs/local-verification.md`](../docs/local-verification.md); this file says where things are and what was true when it was walked.

- **Entry point:** `python -I bin/local-wp.py --site "<Local site name>" <WP-CLI command>`, from the repository root. It reads Local's own site list (`%APPDATA%\Local\sites.json`) at run time, so nothing site-specific is in the repository (no address, folder, Local id, port or credential: the owner's rule). `import <dump.sql>` is the restore (drops every table, then imports through Local's MySQL client on the site's port). Exit 2 for an unknown or doubled name (it prints the names Local knows), a missing PHP / MySQL client / `php.ini` / `wp-cli.phar` / site folder, or a refused `db import` / `db query` (they ignore the port).
- **Webhook capture:** `python -I bin/webhook-capture.py --port <port> --out <file.jsonl>`, 127.0.0.1 only, 200 `{}` to every POST, one JSON line per request. The plugin's `wp_remote_post()` reaches it (`n8n_webhook_url` = `http://127.0.0.1:<port>/…`). It never calls back, so a full n8n round trip still needs a real instance (story 2).
- **Sites:** routine checks run on the showcase, the Local site "Post Quality Showcase" (sample posts, a Free build); the pre-production pass runs on a clean WordPress 6.6 site the owner creates in Local when story 38 nears (hitl), found by its name like any site. Never the owner's production site or its Local copy (`memory/lessons.md` 2026-10-14, 2026-10-24).
- **Each check installs a build** (owner decision 2026-10-26): the Free build (`php bin/build-free.php <out>`, zipped) or the Pro build (`npm run zip`), with `wp plugin install <zip> --force`. A junction to the working tree is documented as a quick-loop option only.
- **Walked 2026-10-26 on the showcase** (WordPress 7.1.3, PHP 8.5.12, MySQL 8.4.0; Local's WP-CLI): backup → Free build of the tree → option write → four role users → `GET /posts` per role (200 for administrator, editor, author; 403 `rest_forbidden` for contributor) → `POST /trigger-review` (200, one captured payload with `X-PQM-Token`, a `processing` row) → Pro build from `npm run zip` → cron run (five captured reviews) → `debug.log` (only WP-CLI's own PHP 8.5 deprecations) → restore (plugin list, table count, review rows, users and `wp-config.php` as before). Every step's expected output is in the doc.
- **Local quirks the doc and the script carry (2026-10-26):** Local's PHP folders carry a `+<build>` suffix `sites.json` lacks; `php_imagick.dll` needs PHP's own `ImageMagick` folder on `PATH`, or every output starts with a startup warning; `wp db export` needs `--port --protocol=tcp` and still warns about the posts table's character set (the dump is complete); `wp db import` and `wp db query` never reach the site's database; a cron event due now is run at once by the site's own WP-Cron, so a walk schedules it an hour ahead and runs it with `wp cron event run`; `wp option patch update` fails on a key the option does not hold yet, `patch insert` sets it either way; on a Free build a Pro command answers 400 `rest_invalid_param` (the command list holds the free agents only); plugin deletion through WP-CLI needs `--user=<an administrator>` on deactivate and uninstall ([[freemium-and-roles]]).
- **Not covered:** the browser (look and feel stays the owner's pass) and the n8n round trip. The pre-production pass itself is still ranked last (owner 2026-10-08) and runs on the release that goes to WordPress.org.
