# LLM options architecture (since 2026-07-23)

Modern Claude models removed/restricted `temperature` (Opus 4.7+ rejects it with HTTP 400; Sonnet 5 rejects non-default values), so the plugin pivoted from "temperature everywhere" to a registry-driven design. Three layers, all in the plugin — the n8n workflow is a dumb executor:

1. **Model registry** — `pqm_model_registry()` in `post-quality-manager.php` is the single source of truth for which request parameters each model accepts (`supports_temperature`, `effort_levels`, `thinking`). Settings UI, sanitizer, admin JS (`pqmAdmin.modelRegistry`), and the param builder all consume it. Supporting a new model = one registry entry.
2. **Param builder** — `pqm_llm_params($agent, $settings)` returns the ready-to-merge Claude request fragment (`model`, `max_tokens`, plus only the knobs the model supports). `pqm_n8n_payload()` (shared by REST trigger + cron) ships a per-agent `llm` map in every webhook payload.
3. **Workflow spreads, never decides** — the six "Build … Body" Code nodes do `{ ...d.llm[agent], system, messages }`; the six parse nodes read the first `text` content block (`find(b => b.type === 'text')`, thinking-proof). LLM option changes therefore **never require a workflow re-import**.

Key decisions (user, 2026-07-23): per-agent model selects with a global default + "inherit"; temperature kept where the model supports it (hidden with a hint otherwise); default model `claude-sonnet-4-6` (no silent behavior change); Custom free-text model ID at the global level only (conservative params: model + max_tokens only). Sonnet 5 gets `thinking: {type: "disabled"}` so adaptive thinking doesn't eat the agents' small output budgets.

**Version handshake:** `PQM_WORKFLOW_VERSION` (main plugin file) must be bumped whenever `templates/n8n-workflow.json` changes in a way that needs a re-import, together with the hardcoded `workflow_version: N` stamp in the template's Parse Input node. The workflow echoes it in `/save-review` callbacks → stored in option `pqm_workflow_version_seen` → the **n8n Workflow** admin page (`pqm-workflow`, `PQM_Admin::render_workflow()`) shows an "update available" notice on mismatch. That page also owns download, import-from-URL, the per-agent request preview, and the connection test; the Settings page keeps only persisted options (all `pqm_settings` fields must stay in the single Settings form — the sanitizer rebuilds the whole array on save).
