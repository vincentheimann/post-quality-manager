# LLM options architecture (since 2026-07-23)

Modern Claude models removed/restricted `temperature` (Opus 4.7+ rejects it with HTTP 400; Sonnet 5 rejects non-default values), so the plugin pivoted from "temperature everywhere" to a registry-driven design. Three layers, all in the plugin — the n8n workflow is a dumb executor:

1. **Model registry** — `pqm_model_registry()` in `post-quality-manager.php` is the single source of truth for which request parameters each model accepts (`supports_temperature`, `effort_levels`, `thinking`). Settings UI, sanitizer, admin JS (`pqmAdmin.modelRegistry`), and the param builder all consume it. Supporting a new model = one registry entry.
2. **Param builder** — `pqm_llm_params($agent, $settings)` returns the ready-to-merge Claude request fragment (`model`, `max_tokens`, plus only the knobs the model supports). `pqm_n8n_payload()` (shared by REST trigger + cron) ships a per-agent `llm` map in every webhook payload.
3. **Workflow spreads, never decides** — the six "Build … Body" Code nodes do `{ ...d.llm[agent], system, messages }`; the six parse nodes read the first `text` content block (`find(b => b.type === 'text')`, thinking-proof). LLM option changes therefore **never require a workflow re-import**.

Key decisions (user, 2026-07-23): per-agent model selects with a global default + "inherit"; temperature kept where the model supports it (since 2026-07-24: slider stays visible but *locked* — `disabled` + dimmed + hint — instead of hidden; same for the effort select; because disabled inputs don't POST, `sanitize_settings()` falls back to the stored value, not the default); default model `claude-sonnet-4-6` (no silent behavior change); Custom free-text model ID at the global level only (conservative params: model + max_tokens only). Sonnet 5 gets `thinking: {type: "disabled"}` so adaptive thinking doesn't eat the agents' small output budgets.

**Decided, not built (ADR 0009, 2026-10-06):** several providers — Anthropic, OpenAI, Google, OpenRouter for free models — through two request shapes (Anthropic Messages + OpenAI Chat Completions); the registry gains a provider per model; the default becomes `claude-sonnet-5-5`; keys stay in n8n credentials; one site-wide monthly token limit from provider-reported usage. Layers 1–3 above stay: the workflow still spreads, never decides. Backlog stories 25, 29, 30; bug 31 first.

**Version handshake:** `PQM_WORKFLOW_VERSION` (main plugin file) must be bumped whenever `templates/n8n-workflow.json` changes in a way that needs a re-import, together with the hardcoded `workflow_version: N` stamp in the template's Parse Input node. The workflow echoes it in `/save-review` callbacks → stored in option `pqm_workflow_version_seen` → the **n8n Workflow** admin page (`pqm-workflow`, `PQM_Admin::render_workflow()`) shows an "update available" notice on mismatch. Current version: **4** (story 35, 2026-10-07). That page also owns download, import-from-URL, the per-agent request preview, and the connection test; the Settings page keeps only persisted options (all `pqm_settings` fields must stay in the single Settings form — the sanitizer rebuilds the whole array on save).

**Failure contract (workflow v3, bug 31):** the HTTP nodes keep "continue on error", so a failed call reaches the next Code node as an item with `json.error`. Every failure item (empty post caught by a Build or Format Score node, model API error with the provider's own text, unparseable agent output, failed rewrite save via `wp.error`, command without a branch in `Error Fallback`) carries `error: true` + a plain `message` naming what failed; `POST Result to WordPress` sends `error_message: $json.error ? ($json.message || 'The workflow could not complete this command. Check the execution log in n8n.') : ''`, and `save_review_callback` stores a non-empty one as status `error` with `result = {error: message}` (the kit's "Could not complete"). Boundary: only failures with a post and a command the plugin accepts reach `/save-review`; Parse Input rejections (missing `command`/`post_id`, or a command outside the `save-review` `command` enum) cannot be stored by contract and show only in the n8n execution log. The IF `Rewrite Parsed?` routes a failed rewrite parse straight to `Format Rewrite Confirmation`, so `Update WP Post (Rewrite)` never PATCHes the post on failure. Guarded by `tests/harness/template-failure-harness.php` (runs the real node code through Node.js) and the template-contract checks in `rest-reviews-harness.php`.

**Secured, host-agnostic connection (workflow v4, story 35, [ADR 0010](../docs/adr/0010-one-token-authenticates-both-directions.md)):** one token, both directions. `pqm_n8n_headers($settings)` (main plugin file) is the one home of the headers every plugin → n8n call sends (Run in `trigger_review_callback()`, cron in `trigger_single_review()`, the test ping): `Content-Type` + `X-PQM-Token: <webhook_token>`. The template's `Webhook Trigger` checks it with n8n Header Auth (credential `Post Quality webhook - __PQM_SITE_HOST__`, header Name field `X-PQM-Token`, Value = the token, picked in the Webhook Trigger only; the Anthropic Header Auth credential goes in the six Claude nodes — the admin copy says which goes where), so the setup needs three credentials; `/save-review` keeps checking the same header on the way back. The payload carries `post_rest_url` = `rest_url(rest_get_route_for_post($post))` (`''` when the post type is not in REST) and `Update WP Post (Rewrite)` PATCHes it as-is — the template assembles no scheme, host or `/wp-json`, so the address is right for any scheme, port, subdirectory and permalink setting. The rewrite itself still needs HTTPS (or environment type `local`): the node signs in with an Application Password, which WordPress core offers only there. `pqm_webhook_url_warning($url)` flags an n8n `/webhook-test/` URL: the ping refuses it before sending, the wizard's `ajax_save_webhook_url()` refuses to store it, the Settings save keeps it and adds a `warning` settings error (printed by `render_settings()` via `settings_errors('pqm_settings')`, since core prints them only under Settings → *). Known limitation: a v3 import ignores the header and the new field, so it keeps running but its trigger stays unauthenticated until the owner re-imports. Skipped until a site reports it: token backfill on upgrade, a 403-specific hint on Run.
