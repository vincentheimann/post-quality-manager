Decided 2026-09-22 (ADR [0003](../docs/adr/0003-freemium-plan-and-role-based-access.md)), **ranked first by `/prioritize` and incepted 2026-10-01** — requirement ids CAP-1…CAP-5 live in `_bmad-output/initiative-post-quality-manager/spec-freemium-and-roles/` (kernel + access-matrix.md companion):

- **Tiers:** free = Review + Key Takeaways; paid = all agents, per-agent overrides, cron, role management. One zip, license key flips the gate. Licensing via Freemius (provider-agnostic `is_pro()` source). Paid plan licensed per site.
- **Roles:** Administrator full · Editor = Author + the four paid agents + per-agent overrides + cron (decided 2026-10-01) · Author = Review + Key Takeaways with a per-user monthly quota (Admin-configured, default 20; decided 2026-10-01) · Contributor nothing. Implemented as plugin capabilities registered on activation, enforced in REST + AJAX.
- **Capabilities (built, story 2, 2026-10-01):** five `pqm_` caps, map + register/remove in `PQM_Features::capabilities()` — `pqm_view_reviews` (Admin, Editor, Author: Dashboard, Post Reviews menus, `GET /reviews`, `GET /post-score`) · `pqm_run_free_agents` (Admin, Editor, Author: review, takeaways; also the fallback for `score` / `apply_*` and the WP-auth path of `/save-review`) · `pqm_run_paid_agents` (Admin, Editor: rewrite, sources, seo, audit) · `pqm_manage_agents` (Admin, Editor: the Settings page + its save since story 5, i.e. the overrides + Automated Reviews sections) · `pqm_manage_settings` (Admin: n8n Workflow menu, the Settings page's admin-only sections, workflow download, webhook save, ping, cron nudge, WP-auth path of `GET /workflow`). Contributor holds none. No `edit_posts` / `manage_options` check remains in the plugin; a role editor remaps everything with no code change.
- **Registration & upgrade:** `PQM_Activator::activate()` grants the default map via `WP_Role::add_cap()` and stores `pqm_caps_version` = `PQM_Features::CAPS_VERSION`; `PQM_Activator::maybe_upgrade()` on `init` re-registers when the stored version is behind (zip-replaced installs are never locked out; bump `CAPS_VERSION` whenever `capabilities()` changes). No `remove_cap` on deactivation — only `uninstall.php` strips the caps and deletes the option. Reactivation re-grants the defaults, so a cap a role editor *removed* from a default role comes back on reactivate (standard WP behavior); grants they *added* persist.
- **Hidden vs locked:** `PQM_Features::why_not( $command )` returns `'role'` (lacks the cap) before `'plan'` (paid tier, unlicensed) — nothing to upsell to a role that cannot run the agent. REST/AJAX answer 403 `pqm_feature_gated` with role copy ("%s is not available for your role. Ask an administrator to extend it.") or the upgrade copy. JS bridge: `pqmAdmin.hiddenCommands` (`hidden_commands()`, buttons not rendered) and `pqmAdmin.gatedCommands` (`gated_commands()`, visible-but-locked) are disjoint; the PHP "Run Review" button follows `can('review')`. `POST /trigger-review` and the AJAX handler share `PQM_REST_API::check_can_trigger()` (any registry cap) as the route gate; the exact per-command decision stays in `trigger_review_callback()`.
- **Presentation** (decided 2026-10-01): plan-gated features visible but locked with upgrade copy; role-gated features hidden.
- **Gate:** single `PQM_Features::can()` combining plan + capability. One n8n template; the plugin refuses gated commands before the webhook. **Built (story 1.1, 2026-10-01):** `includes/class-pqm-features.php` — `registry()` (six agents, tiers per the access matrix, capabilities `pqm_run_free_agents` / `pqm_run_paid_agents` since story 2), stub `is_pro()` behind the public `pqm_is_pro` filter (mu-plugin `__return_true` demos the paid path until story 3), one gate call in `PQM_REST_API::trigger_review_callback()` covering REST + AJAX + GET fallback; paid buttons render visible-but-locked via `pqmAdmin.gatedCommands`. `score`/`apply*`/`ping` and cron are outside the gate by design.
- **Author quota (built, story 4, 2026-10-01; spec CAP-4):** per user, per calendar month (site timezone), for anyone *without* `pqm_run_paid_agents` — `PQM_Features::is_quota_subject()`; granting paid agents lifts the quota, no new capability, `CAPS_VERSION` unchanged. Storage is one self-resetting user meta `pqm_monthly_usage` = `['month' => 'YYYY-MM', 'count' => N]` (schema unknown resolved 2026-10-01: user meta, no usage table): a stale month reads as 0 and is overwritten on the next increment, so there is no reset cron. Setting `author_quota` (shipped default 20; Settings → "Monthly Quota", Admin-only via `pqm_manage_settings`, `absint`-sanitized; **0 = unlimited** escape hatch → `quota_state()` returns null, same as exempt). Enforced only in `PQM_REST_API::trigger_review_callback()` — the single chokepoint behind REST, AJAX and the Post Reviews GET fallback — *after* the feature gate, so role/plan refusals keep priority: `pqm_quota_exceeded` 429 with count + reset-date copy. `consume_quota()` runs only after the n8n webhook answers 2xx: refusals, unreachable n8n and non-2xx answers never spend an action; non-registry commands (`score`, `apply*`) consume too. Cron (`PQM_Cron`) posts to n8n directly and never enters the callback → quota-free by construction. UI: `pqmAdmin.quota` (= `quota_state()`: `limit`/`used`/`remaining`/`resets`, null when exempt/unlimited) renders `.pqm-quota-note` ("%1$d of %2$d AI actions left this month") beside the Post Reviews filters (PHP) and next to every action button in the detail panels (JS `quotaNote()`), live-updated from the AJAX/REST `quota_remaining` field. `uninstall.php` deletes the meta for all users via `delete_metadata('user', 0, …, true)`.
- **Settings sections (built, story 5, 2026-10-01; spec CAP-3):** the Settings page and `option_page_capability_pqm_settings_group` moved to `pqm_manage_agents` (Admin + Editor); sections follow the access matrix — n8n Connection, AI Model, AI Prompts & Context and Monthly Quota are *hidden* without `pqm_manage_settings`; Agent-Specific Overrides and Automated Reviews are *plan-locked* (visible, upgrade copy, wrapped in one `<fieldset disabled class="pqm-locked-section">` — JS-proof, nothing inside POSTs) when `is_pro()` is false, for Admins too. Role-hidden beats plan-locked. **Sanitizer carry rule** (`sanitize_settings()`): section-wise, never per-field — admin-only keys (`n8n_webhook_url`, `webhook_token`, `notification_url`, `blog_profile`, `brand_voice_preset`, `brand_voice`, `website_context`, `default_model`, `custom_model`, `author_quota`) come from `$input` only when the saver has `pqm_manage_settings`, else from the *stored* settings; `cron_*` + `agent_prompts` come from `$input` only when the site is pro, else carried wholesale from stored (so a locked `cron_enabled = true` survives the absent checkbox; the per-knob stored fallback for model-locked temperature/effort stays on the pro path). JS: every settings block guards on its own elements; `pqmAdmin.defaultModel` (effective global default, Custom resolved) feeds the model-caps refresh when the AI Model section is absent. n8n Workflow page stays `pqm_manage_settings`.
- **Distribution:** GitHub Releases first, WordPress.org later with the same gate (updates the "deferred" stance in [[pivot-agnostic]]).
