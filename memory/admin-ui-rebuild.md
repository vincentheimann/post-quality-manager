# Admin UI rebuild — Dashboard & Post Reviews

Decided 2026-10-02 (ADR [0005](../docs/adr/0005-wordpress-components-for-app-screens.md), owner-approved ticket-7 UX review). **Tracer bullet built 2026-10-02** (epic-ui-rebuild story 5.1): repo-root `package.json` + `@wordpress/scripts` build (`src/` → `post-quality-manager/admin/build/`, assets git-ignored, CI builds them in `.github/workflows/ci.yml`), read-only `GET post-quality/v1/posts` route, and the React Post Reviews table shell. Legacy `render_posts()` + its GET trigger path are unreachable but still in the file — deletion is story 5.7. **Component kit built 2026-10-02** (story 5.2): `src/kit/` is the one JS source for status badges, progress pills, the quota note and command/gate copy (`copy.js` — `COMMAND_ORDER`, `commandLabel()`, locked-button copy), strings through `@wordpress/i18n`; its CSS is extracted to `build/style-index.css` (+ RTL twin). `GET /posts` carries an additive `viewer` block (`can_trigger`, `quota` — null when exempt or when the viewer cannot trigger — `gated_commands`, `hidden_commands`) that mirrors `PQM_Features`; stories 5.3–5.6 read gating and quota from it, never from a localized snapshot. **Filters, sorting and pagination built 2026-10-05** (story 5.3): `GET /posts` gained additive `status` (four stored values + `none` = never reviewed or an empty latest status — the failed-run fallback, story 5.6 fix), `min_score`/`max_score` (0–100, HAVING on the latest score), `orderby=status` (severity via `PQM_DB::status_order_expression()`, reusable by the 5.6 queue) and a filter-independent `counts` block (`all/ship/needs_revision/major_revision/none`) between `pages` and `viewer`; bad values clamp, never error. Score bands follow the plugin thresholds (Below 41 / 41–70 / 71+ = ScoreBadge colors). The table keeps its state in the URL (`status`, `min_score`, `max_score`, `orderby`, `order`, `paged`, `history.replaceState`) so tiles can deep-link; the legacy `?filter=needs_review` Dashboard link still passes through (no chip pressed). `statusLabel()` in `src/kit/copy.js` is the one source for status labels (StatusBadge + chips); page-local components live in `src/post-reviews/`. **Detail panel + trigger flow built 2026-10-05** (story 5.4): a per-row Details toggle (`aria-expanded`/`aria-controls`, disabled only while the post is *actively awaited*) opens `src/post-reviews/detail-panel.js` — a `@wordpress/components` `TabPanel` (Review with single-hue pillar meters + top edits + actions, one tab per agent through the generic `result-view.js` renderer, History) fed by `GET /reviews/{id}` (now up to 50 rows, int `overall_score`, `reviewed_at_display`). Rewrite is a button in the Review action row, never a tab; a plan-locked button is `aria-disabled` + no-op (focusable on every supported WP). Triggers call `POST /trigger-review` directly, no confirm for a single run; the `processing` placeholder row is written **once, server-side, in `trigger_review_callback()` after an n8n 2xx** (moved out of `ajax_trigger_command()`). **`PQM_DB::latest_review_subquery()` excludes `processing`**: a post's `latest_*` is its last *result*, so a running review never changes list membership, order or counts; `GET /posts` items carry an additive `in_flight` list (`PQM_DB::get_in_flight_for_posts()`, latest row per post+command is `processing`) and the row shows Processing from it. One `use-polling.js` hook (3 s, server-state driven, auto-resumes on load for any command/locale) refetches the list silently; completion = the command left `in_flight` *or the post left the same query* (its result moved it); a query change resets tracking; per key 3-min give-up (Details returns, entry kept, `restart()` re-arms on a new trigger). Stored dates are GMT — both display dates go through `get_date_from_gmt()` (5.1 bug fixed). Outcomes toast through `toasts.js` (`SnackbarList`, self-announcing — the page keeps one `role="status"` host, 5 s, no `wp-data`). A failed run — stored `error`, or the template's real fallback (empty status + `{}`) — is surfaced only by the toast and the panel (owner decision 2026-10-05); the list still shows "Not analyzed"; the kit's `error` badge ("Could not complete", neutral, `dismiss`) lights up once the template sends `status: 'error'` (deferred-work.md). New kit copy: `runLabel()`, `FREE_COMMANDS`, `error`/`rewritten` status labels. New class names avoid the still-loaded legacy `pqm-admin.css` (`.pqm-expanded-row`, `.pqm-panel-actions`, `.pqm-top-edits`, `.pqm-run-history`, `.pqm-locked` is unclaimed there). **Bulk Review selected built 2026-10-05** (story 5.5, manual site pass pending): `startRun( postId, command )` in `src/post-reviews-table.js` is the one trigger path (`Promise<{ ok, message }>`, never rejects; success re-arms polling + silent refetch) used by the single Run and by `src/post-reviews/bulk-bar.js`. Viewers passing the panel's `canRender( viewer, 'review' )` (exported from `detail-panel.js`) get a checkbox column + select-all (page-local, cleared on any query change and at batch start, in-flight rows not selectable) and the bulk bar: one `Modal` confirmation (count + remaining quota), then one `POST /trigger-review` per post strictly in sequence; refusals are reported per post and the queue continues; outcomes fill an inline dismissible `Notice` by title. No new route, no PHP change. **Dashboard built 2026-10-05** (story 5.6, manual site pass pending): the Dashboard is a React page on the same bundle (`src/index.js` mounts `src/dashboard.js` on `#pqm-dashboard-root`); PHP ships only the shell — `PQM_Admin::render_app_shell( $title, $root_id )` is shared with Post Reviews, `render_dashboard_app()` keeps the cron-nudge dismiss handler, the Dashboard hook is captured like the Post Reviews one, and both enqueue `enqueue_app()` (script/style handle `pqm-app`). Legacy `render_dashboard()` + `PQM_DB::get_dashboard_stats()` are unrouted, deletion is story 5.7. Queue = `GET /posts?orderby=priority&per_page=5` (`PQM_DB::PRIORITY` + `priority_order_sql()`: Major → Needs → Not analyzed (NULL/empty status), then score ASC, oldest review, oldest post, ID; `order` ignored; ship rows dropped client-side). One read route `GET /dashboard` (`check_view_reviews`): `average_score`, `trend[{label, average}]` (8 week ends, last = now, so the last point *is* the average; `PQM_DB::get_score_trend()` walks every non-processing review row in PHP — ceiling noted, upgrade = stored weekly snapshots), `connected`, `can_manage_settings`, `cron_nudge`, `cron_nudge_dismiss_url` (only when shown; raw URL, nonce). The average counts only posts whose latest result is ship / needs_revision / major_revision. Tiles mirror the chips (Average → `?orderby=score&order=asc`; Major / Needs / Not analyzed / Ready → `?status=…`, numbers from the same `counts`). Sparkline = inline SVG in `src/dashboard/sparkline.js` (no chart library). **One trigger source:** `src/kit/runs.js` (`requestRun()`, `outcomeToast()`, `settledToast()`, requested / give-up copy) is shared by Post Reviews (`startRun` = `requestRun` + polling re-arm) and the Dashboard queue; `use-polling.js` and `toasts.js` moved from `src/post-reviews/` into `src/kit/`. Dashboard classes avoid the legacy `.pqm-card`, `.pqm-stat-*`, `.pqm-stats-grid`, `.pqm-dashboard-cta` (`.pqm-tile*`, `.pqm-queue*`, `.pqm-spark*`, `.pqm-dash-*`).

- **Framework:** the Dashboard and Post Reviews pages are rebuilt on `@wordpress/components` + `@wordpress/element` with an `@wordpress/scripts` build; React loads from WordPress itself (dependency extraction). **Settings and n8n Workflow stay on the PHP Settings API** — no rebuild there.
- **One render source:** PHP renders only the page shell; every badge, pill, row and panel renders client-side from the existing REST API. This retires the duplicated PHP/JS markup (and subsumes backlog story 5, CSS classes for JS markup). i18n via `@wordpress/i18n` — fixes the hardcoded-English JS copy and the `indexOf('Processing')` auto-resume bug on translated sites.
- **Design source of truth:** `_bmad-output/initiative-post-quality-manager/ux-dashboard-post-reviews/` — DESIGN.md (findings F1–F6, decisions D1–D7, owner decisions incl. queue length 5 and bulk "Review selected" in the first slice) + mockup.html (interactive reference of the target UX).
- **Components over browser natives (owner, 2026-10-05):** in the React pages, dialogs, confirmations and similar UI use `@wordpress/components` (e.g. `Modal`) by default, not `window.confirm()`/`alert()` or bare native widgets. On the minimal-code ladder's rung 4, this owner preference wins when WordPress and the browser both cover a need. Ask before choosing a browser native.
- **Status language:** icon + label + color, never color alone; no emoji. The WP status colors fail deutan red↔green separation as a bare palette (validator run 2026-10-02) — the icon+label rule is load-bearing, not decoration.
- **Sequencing:** own epic via `bmad-spec` + `bmad-ticket`, built after `epic-freemium-and-roles` closes (stories 1.7/1.8). Story 1.7 keeps only non-UI cleanup; UI-rendering cleanup (dead GET trigger path, `apply_` branch, unused CSS, inline styles) belongs to the rebuild epic.
- **Unchanged by the rebuild:** the feature gate, quota, REST/webhook contracts, the n8n template — ADR 0005 changes rendering only.
