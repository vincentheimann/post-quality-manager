Template updates become `PUT /workflows/{id}` (auto-republish, ends the re-import handshake), token rotation becomes `PATCH /credentials/{id}`. Not built yet. **Spec written 2026-10-13** (`_bmad-output/initiative-post-quality-manager/spec-n8n-provisioning/`: kernel CAP-1..8, `failure-modes.md`, `brownfield.md`, the spike findings adopted as companion): one epic — connect by key, fresh provisioning, rollback, adopt-existing, one-click template update, token rotation, mis-wiring diagnosis (new: on 2026-10-13 the owner's production n8n had the one Header Auth credential auto-assigned to all seven nodes on import, so every AI call failed silently), manual fallback absorbing story 40. **Epic incepted 2026-10-13** as `epic-n8n-provisioning` (initiative epic 6, covers UV4, 12 entries in `tickets.toml`): 1 connect by key (tracer, hitl probe), 2 manual fallback (absorbs story 40, dropped by reference), 3 per-site webhook path (the epic's one `PQM_WORKFLOW_VERSION` bump, to 6), 4 server provisioning, 5 rollback, 6 the wizard (exposes provisioning only after rollback), 7 mis-wiring diagnosis (hitl: the owner's production workflow), 8 adopt, 9 one-click template update, 10 token rotation, 11 refactor sweep, 12 success-signal walk + records. What is true now:

- **Entry 1 built 2026-10-13** (PRs #106 and #107 merged 2026-10-13, entry done; HITL walk passed the same day on the owner's production site, run by the agent at the owner's request): `PQM_N8n` (`includes/class-pqm-n8n.php`) is the n8n API client every later entry calls — `request($method, $path, $body)` on the stored instance (`/api/v1` prefixed, plugin User-Agent, `X-N8N-API-KEY`, no redirects) and `probe($url, $key)`; base URL + key + last passing probe live in option `pqm_n8n_api` (autoload off, deleted on uninstall). `GET|POST|DELETE /n8n/connection` (`pqm_manage_settings`) back the "n8n Instance" island (`src/n8n-connection/`) on the n8n Workflow page; the key is never in a reply. HITL probe 2026-10-13 on the owner's instance (2.42.3): no version is exposed to an API key (the section says "Connected to n8n."); a missing route answers the router's generic `404 {"message":"not found"}`, an existing one its handler's message, a body-less PATCH 415 — the probes send `{}` and `n8n-api-harness.php` scripts the observed shapes.

- The n8n API key will be **stored** in settings (owner accepted the blast radius; mitigations: dedicated expiring key, Forget button, HTTPS-only base URL, plugin-identifying `User-Agent` — generic agents get WAF-banned).
- The provider key passes through the plugin **once** during setup: validated by a direct provider call (n8n's credential test is a no-op for generic types), written to the n8n credential, never stored. ADR 0009 stands; `docs/policies/` copy must change to "forwarded once, never stored" in the same epic.
- Adopt-existing lists credentials (metadata only, never secrets) and asks the owner to confirm; deterministic names are trusted only for wizard-created setups.
- The webhook path becomes per-site (static `pqm-execute` collides on a shared instance).
- The manual import path remains the fallback: Cloud trial, disabled API, older n8n. Everything is confirmed on 2.42.3 only; the wizard probes and degrades.
- Rollback order on failed provisioning: deactivate → delete workflow → delete credentials (active workflows refuse DELETE with 409; credentials delete silently even while referenced).

Product decisions for the spec (owner-delegated, 2026-10-12):

- Provisioning is a **free** feature: UV4 is the evaluation funnel, Pro sells outcomes (ADR 0003), the manual path is the fallback, not the free tier.
- Adopt vs fresh: a connected site with a green handshake defaults to "keep existing" (key stored for future updates, credential mapping only with explicit confirmation); an unconfigured site defaults to fresh provisioning; nothing manual is ever auto-deleted.
- The n8n API key lives on the **n8n Workflow page** (page-local merge-save, write-only masked field, "set / not set" + Forget) — never in the Settings form, which re-echoes values.
- Sequencing: story 55 (wizard continuation) builds first; the provisioning epic reworks the n8n connection steps afterwards and absorbs story 40 as the manual-fallback story.
