# n8n provisioning

Decided 2026-10-12 (ADR 0015, from spike 56): the setup wizard will provision n8n through its public API — create the three credentials, create/activate the workflow with per-node credential ids, compute the webhook URL, verify with ping. Template updates become `PUT /workflows/{id}` (auto-republish, ends the re-import handshake), token rotation becomes `PATCH /credentials/{id}`. Not built yet. **Spec written 2026-10-13** (`_bmad-output/initiative-post-quality-manager/spec-n8n-provisioning/`: kernel CAP-1..8, `failure-modes.md`, `brownfield.md`, the spike findings adopted as companion): one epic — connect by key, fresh provisioning, rollback, adopt-existing, one-click template update, token rotation, mis-wiring diagnosis (new: on 2026-10-13 the owner's production n8n had the one Header Auth credential auto-assigned to all seven nodes on import, so every AI call failed silently), manual fallback absorbing story 40. **Epic incepted 2026-10-13** as `epic-n8n-provisioning` (initiative epic 6, covers UV4, 12 entries in `tickets.toml`): 1 connect by key (tracer, hitl probe), 2 manual fallback (absorbs story 40, dropped by reference), 3 per-site webhook path (the epic's one `PQM_WORKFLOW_VERSION` bump, to 6), 4 server provisioning, 5 rollback, 6 the wizard (exposes provisioning only after rollback), 7 mis-wiring diagnosis (hitl: the owner's production workflow), 8 adopt, 9 one-click template update, 10 token rotation, 11 refactor sweep, 12 success-signal walk + records. The workflow menu is "Import" → "From URL" / "From file"; credentials are created from the arrow beside "Create workflow" on the Overview page ("Create credential"); the chevron beside "Publish" holds "Unpublish". Credential filling: an import drops the template's credentials (names without ids) and gives non-HTTP-Request nodes (the Webhook Trigger) the most recently saved credential of their type; opening a node fills an empty one the same way; a credential picked by hand is added to every other empty node accepting that type ("Added this credential to N other node(s)"). So a webhook credential picked first spreads to all Claude nodes, the likely path of the 2026-10-13 mis-wiring; the Workflow File section has the Claude nodes done first.
- The manual import path remains the fallback: Cloud trial, disabled API, older n8n. Everything is confirmed on 2.42.3 only; the wizard probes and degrades.
- Rollback order on failed provisioning (built in entry 5): deactivate → delete workflow → delete credentials, no credential before the workflow delete passed (published or still-unpublishing workflows refuse DELETE with 409; credentials delete silently even while referenced).
