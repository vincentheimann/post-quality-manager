# n8n provisioning

Decided 2026-10-12 (ADR 0015, from spike 56): the setup wizard will provision n8n through its public API — create the three credentials, create/activate the workflow with per-node credential ids, compute the webhook URL, verify with ping. Template updates become `PUT /workflows/{id}` (auto-republish, ends the re-import handshake), token rotation becomes `PATCH /credentials/{id}`. Built 2026-10-13 → 2026-10-16 (entries 1–12, PRs #106–#144; the success-signal walk 2026-10-16, Entry 12 line below). **Spec written 2026-10-13** (`_bmad-output/initiative-post-quality-manager/spec-n8n-provisioning/`: kernel CAP-1..8, `failure-modes.md`, `brownfield.md`, the spike findings adopted as companion): one epic — connect by key, fresh provisioning, rollback, adopt-existing, one-click template update, token rotation, mis-wiring diagnosis (new: on 2026-10-13 the owner's production n8n had the one Header Auth credential auto-assigned to all seven nodes on import, so every AI call failed silently), manual fallback absorbing story 40. **Epic incepted 2026-10-13** as `epic-n8n-provisioning` (initiative epic 6, covers UV4, 12 entries in `tickets.toml`): 1 connect by key (tracer, hitl probe), 2 manual fallback (absorbs story 40, dropped by reference), 3 per-site webhook path (the epic's one `POSTQUALITY_WORKFLOW_VERSION` bump, to 6), 4 server provisioning, 5 rollback, 6 the wizard (exposes provisioning only after rollback), 7 mis-wiring diagnosis (hitl: the owner's production workflow), 8 adopt, 9 one-click template update, 10 token rotation, 11 refactor sweep, 12 success-signal walk + records. Owner decisions at inception: the manual path is open by choice (the wizard leads with the key, "Set up by hand instead" secondary); policy wording ships with the story that makes it true (entries 1 and 6); CAP-7 finds a manual workflow by the saved webhook URL's path, read-only; the n8n URL and key get their own option, not `postquality_settings`; rollback also revokes the generated Application Password.
