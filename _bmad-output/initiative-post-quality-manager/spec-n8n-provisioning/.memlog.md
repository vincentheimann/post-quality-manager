- (direction) Owner 2026-10-13: spec only in this session; bmad-ticket slices the epic in a fresh session; no build here.
- (decision) One epic. Scope: fresh provisioning from the wizard, adopt an existing manual setup with owner-confirmed mapping, one-click template update (PUT) and webhook-token rotation (PATCH), the manual fallback rewritten from story 40 with probe-and-degrade (owner 2026-10-13, recommended option).
- (decision) Provisioning is a free feature: UV4 is the evaluation funnel, Pro sells outcomes (ADR 0003); the manual path is the fallback, not the free tier (owner 2026-10-12).
- (decision) The n8n API key is stored in settings; blast radius accepted (unscoped key reaches n8n from a WP compromise) with mitigations: dedicated expiring key, Forget button, HTTPS-only base URL (localhost excepted), plugin-identifying User-Agent on every n8n call (ADR 0015).
- (decision) The key lives on the n8n Workflow page only: write-only masked field, page-local merge-save, shows set / not set + Forget; never in the Settings form, which re-echoes values (owner 2026-10-12).
- (decision) The provider key passes through once: validated by one cheap Anthropic request (n8n has no test for generic credential types), written into the n8n credential, never stored or logged; ADR 0009 stands, the policy copy changes to "forwarded once during setup, never stored" in this epic (ADR 0015; owner 2026-10-13: Anthropic only).
- (decision) Adopt vs fresh: a connected site with a green handshake defaults to keep existing (key stored for later updates; credential mapping only with explicit confirmation); an unconfigured site defaults to fresh provisioning; nothing manual is ever auto-deleted (owner 2026-10-12).
- (decision) Adoption lists credentials and workflows via GET (metadata only, never secrets) and asks the owner to confirm the mapping; deterministic names are trusted only for setups the wizard created (spike finding 3).
- (decision) The webhook path becomes per-site (derived from the site host) instead of the static pqm-execute, ending collisions on a shared instance (spike finding 5).
- (decision) Rollback order on any failed provisioning: deactivate, then delete workflow, then delete credentials; the API refuses DELETE on an active workflow (409) and deletes credentials under an active workflow without complaint (spike finding 4).
- (decision) Everything is confirmed on self-hosted n8n 2.42.3 only; the wizard probes the instance (reachability, API enabled, version, endpoints) and degrades to the manual path with a version hint instead of failing (spike finding 6).
- (decision) Mis-wiring diagnosis is in scope: with the key stored, the handshake reads the workflow's node credentials and reports a Claude node that carries the trigger's credential, or a credentialed node with none; motivated by the 2026-10-13 silent failure on the owner's production site where n8n auto-assigned the one Header Auth credential to all seven nodes on import (owner 2026-10-13).
- (decision) Success signal: a fresh site reaches its first review with only the n8n base URL, an n8n API key and the Anthropic key typed into the plugin and no visit to the n8n UI; proven by a HITL walk on the owner's instance from an empty n8n project, recorded with the environment the owner names (owner 2026-10-13).
- (decision) Non-goals: multisite, n8n Cloud trial (no public API), providers other than Anthropic (ADR 0009 epic), any change to the Pro gate, scoped or project-bound n8n keys (Enterprise), storing the provider key, n8n screenshots in the plugin (owner 2026-10-13; story 36 decision 2026-10-07).
- (capability) CAP-1 Connect an n8n instance by key: base URL + API key on the n8n Workflow page; probe; set / not set + Forget. Success: a valid key shows connected with the instance version; a WAF ban, a disabled API or an old version shows the named cause and the manual path.
- (capability) CAP-2 Fresh provisioning from the wizard: Anthropic key validated once; Application Password generated; three credentials, the workflow (per-site path, credential ids linked), activation, webhook URL and token saved, ping green. Success: the success-signal walk.
- (capability) CAP-3 Failed provisioning leaves nothing behind: forced failure at each step rolls back in the forced order and names the failed step with its cause. Success: zero plugin-created objects after each forced failure, verified via the API.
- (capability) CAP-4 Adopt an existing manual setup: candidates listed from metadata, mapping proposed, owner confirms, key stored; nothing deleted. Success: the owner's manual setup adopted and CAP-5/6/7 work on it.
- (capability) CAP-5 One-click template update: PUT of the current template on the provisioned or adopted workflow, credential ids and path preserved; replaces the re-import notice. Success: after a version bump the ping reports the new version with no re-import.
- (capability) CAP-6 Webhook-token rotation as a plugin action: new token generated, credential PATCHed, settings saved. Success: the old token is refused and the new one accepted on the next request.
- (capability) CAP-7 Mis-wiring diagnosis in the handshake. Success: the 2026-10-13 situation (Claude nodes carrying the trigger credential) is reported in one sentence with the fix; a wizard-provisioned workflow reports clean.
- (capability) CAP-8 Manual fallback (absorbs story 40): the Workflow File section as ordered steps with Copy buttons and accurate links, plus a warning that n8n assigns the first existing credential to every node on import; it is the path offered when the API is unavailable. Success: story 40 acceptance criteria, plus the warning present.
