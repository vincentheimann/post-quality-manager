## Intent

**Problem:** The template's Webhook Trigger listens on the static path `pqm-execute`, so two sites on one n8n instance, or a provisioned workflow beside a manual import, collide (spike finding 5); entry 4 needs a path the plugin computes per site, and the downloaded, imported and provisioned workflows must all carry the same one.

**Approach:** A `__PQM_WEBHOOK_PATH__` placeholder beside `__PQM_SITE_HOST__`, filled by `pqm_workflow_json()` from one new helper that later entries reuse; `PQM_WORKFLOW_VERSION` 5 → 6 stamped in its three places; the outdated-workflow copy tells a re-importing site that its production URL changes.

## Boundaries & Constraints

**Always:** `templates/n8n-workflow.json` stays placeholders-only and the Free template is regenerated by `php bin/derive-free-template.php`, never edited by hand; the define, Parse Input's stamp and the trigger's reply all say 6 (`rest-reviews-harness.php` checks the three agree); `pqm_workflow_json()` is the one filler and `pqm_webhook_path()` the one derivation of the path (entries 4, 7 and 8 call it, never recompute it); the derivation uses no filterable WordPress function, so every context yields the same path; the guard lists the new placeholder and fails on a literal trigger path; one line in `docs/release-notes/unreleased.md`; copy per `docs/brand.md`.

**Never:** an n8n API call or a change to `PQM_N8n`; a change to the callbacks' REST contract, to `sanitize_settings()`, to `pqm_webhook_url_warning()` or to the saved `n8n_webhook_url` (no migration: the plugin cannot know the new workflow's URL, and an adopted manual setup keeps its own path, CAP-4); a check of the saved URL's path against the site's; another template change or version bump (this is the epic's one); the wizard's steps beyond the placeholder text; a `webhookId` on the trigger.

**Decisions (owner, 2026-10-13, recommended answers):**
- D1 Path form: a readable host slug, `pqm-execute-<host-slug>` (e.g. `pqm-execute-example-com`), from the same host as the credential names; not the spike's hash.
- D2 What a re-importing site is told: copy only. The update notice, the two outdated ping messages and the release-notes line say a re-import gives a new production URL to copy from the Webhook Trigger and paste here; the saved URL is left alone, no path-mismatch warning (an adopted manual setup keeps its own path, CAP-4).
- D3 Plan size: keep the full plan (one goal; the length is the Code Map).

## Design Notes

- Derivation: `'pqm-execute-' . trim(preg_replace('/[^a-z0-9]+/', '-', strtolower(pqm_site_host())), '-')` (PHP stdlib, rung 3). Not `sanitize_title()`: it runs the `sanitize_title` filter, so a plugin could make the path differ between the download and entry 4's provisioning. The `pqm-execute-` prefix stays so entries 7 and 8 recognise plugin paths with one `str_starts_with()`.
- Fill: `str_replace(['__PQM_SITE_HOST__', '__PQM_WEBHOOK_PATH__'], [pqm_site_host(), pqm_webhook_path()], $json)`.
- Copy: keep "Workflow update available." as the notice's first sentence (the jsdom fixtures match it); append one sentence: the re-imported workflow listens on a new production URL, copy it from the Webhook Trigger and paste it here. Same sentence at the end of the two outdated ping messages.
- Skipped: a status warning when the saved URL's path is not this site's — an adopted manual setup keeps its own path (CAP-4), entry 9 keeps the workflow's current path. Skipped: a `webhookId` — n8n assigns one on import and create.
