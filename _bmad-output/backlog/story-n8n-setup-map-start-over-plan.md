## Intent

**Problem:** Once the plugin has provisioned or adopted a workflow, its setup map can only go with uninstall. A site that moves to another n8n instance, or whose workflow was deleted in n8n, is refused provisioning and adoption, keeps offering Update and Rotate against ids the new instance never had, and a stored mis-wiring sentence can never clear. Leftovers of a previous instance are dropped without a word.

**Approach:** a **Start over** action in the n8n connection disclosure (beside the managed line, a `@wordpress/components` Modal for the confirmation) that clears the map, the saved webhook URL and the version report, revokes the Pro Application Password (bug 73's helper) and, when the Administrator keeps the offer ticked, removes the mapped workflow and credentials on n8n by id in the rollback order, keeping what n8n refuses in the leftovers record. The map stores the instance it was made on (`base_url`); the managed gates and the diagnosis-by-id compare it, so a connection to another instance stops Update and Rotate with a sentence naming the instance and Start over. A gone workflow is named on a 404 test ping and on the managed actions, with Start over as the way out. Leftovers of a previous instance are named in the provisioning reply when dropped, and the wizard says so beforehand.

**Decisions taken at planning (owner to confirm at the checkpoint):**
- D1: Start over clears the saved webhook URL and the version report with the map, so the page lands in state 2 (connected, not set up) as AC1 asks; the n8n key stays (the ticket's open question: Forget key and Start over remain two actions).
- D2: the removal offer is a checkbox in the Modal: ticked by default for a wizard-created setup, unticked with a warning for an adopted one ("made by hand in n8n"); it is not offered at all when the connected instance is not the map's (nothing is sent to the new instance with old ids, AC2) or no key passes, and the Modal says the objects stay where they are.
- D3: a map without `base_url` (stored before this story) counts as the connected instance's; nothing changes for it until the Administrator starts over.
- D4: the gone-workflow sentence on a test ping costs one n8n read, only when a 404 ping meets a same-instance map with a key that passes; every other ping stays as it is.

## Boundaries & Constraints

**Always:** n8n objects are touched only by the ids the map holds, never by name; removal follows `roll_back()`'s order (deactivate, workflow, credentials) and what n8n refuses goes to `LEFTOVERS_OPTION` with the map's `base_url`; nothing is sent to an instance other than the map's; the Pro revoke stays behind Freemius markers; `@wordpress/components` for the Modal (owner rule, no `window.confirm()`); copy per `docs/brand.md`; every new behaviour has a harness or Jest row; one `docs/release-notes/unreleased.md` line.

**Never:** a change to what provisioning, adoption, update and rotation do on a map that matches the connected instance; a change to the webhook token or the manual path; forgetting the n8n key as part of Start over; a Danger Zone or any Settings-page change (story 69); a REST or payload change for the n8n workflow template; deleting objects without the Administrator's confirmation.

## Design Notes

- Start over is a React action inside the island, not a PHP `[data-pqm-post]` button like Rotate: it needs a confirmation with a choice, which the owner's rule puts in a `@wordpress/components` Modal (memory/admin-ui-rebuild.md, 2026-10-05). The island already owns the managed line and the adoption block's Notice, so the reply's error lands there.
- The clears (URL and report) happen even when n8n refused part of the removal: the site has started over; what remains in n8n is the leftovers record's business, removed before the next provisioning as entry 5 built it. A removal is never retried from Start over.
- `same_instance()` compares the stored `base_url` with `connection()['base_url']` as strings (both are `origin()` output); a map without the key is same-instance (D3), so every existing harness row keeps its meaning.
- Copy (brand.md: gentle cause, actionable fix). Modal body: "Start over removes the setup from this site: the plugin forgets the workflow and credentials it manages, the n8n Webhook URL and the last test. Your n8n API key stays. You can set n8n up again right after." Checkbox: "Also remove the workflow and its credentials in n8n". Hand-made warning: "This workflow and its credentials were made by hand in n8n. Leave the box unticked to keep them." Other instance: "Your workflow and credentials stay on %s: the plugin does not touch an instance it is not connected to."
- Skipped: a retry button for leftovers (entry 5's next-provisioning cleanup covers it); forgetting the key (D1); a Start over for a hand-made setup without a map (there is nothing to clear but the URL, which the Webhook disclosure edits).
