## Intent

**Problem:** A site that opted in to Freemius usage data and later opted out still sees the deactivation feedback form, and the reason it gives is sent to Freemius, because bug 90's filter reads `is_registered()`, which stays true after an opt-out (SDK 2.13.5 docblock L10697–10704). The privacy policy says usage data can be switched off at any time.

**Approach:** Decision (owner, 2026-10-26, "filter + privacy line"): the filter also requires `is_tracking_allowed()`, so the form opens only on a site that shares usage data now. Decision (owner, 2026-10-26, after review pass 1, "describe it fully", replacing the one-sentence description): the privacy texts state everything an opted-out site can still send. Decision (owner, 2026-10-26, after review pass 2, "fix leak + general text", replacing "describe it fully" and its wording): (1) at deletion, a site that does not share usage data now has any stored feedback answer removed before the SDK's uninstall event runs, so it sends no reason and the SDK never re-runs the opt-in with the admin's name and email; (2) the privacy texts hold on every build and opt-out path without listing SDK fields. Wording, in "Optional usage data": "under the plugin's settings" becomes "with the Opt In or Opt Out link under the plugin on the Plugins screen", and after "…sends nothing then or when it is deleted." goes: "Opting out stops the usage data above and the feedback form, and a site that does not share usage data when the plugin is deleted sends no feedback answer. Freemius may still receive technical updates about the plugin's installation on the site, such as its version, the site address and whether the plugin is active, and the list of plugins and themes unless you switched that off too. On a site without a Pro license, Disconnect on the plugin's Account page deletes the record Freemius holds for the site." Short version, after "…not even when you deactivate or delete the plugin.": "After an opt-out, Freemius may still receive the technical updates described under Optional usage data." The readme text and the release note carry the same facts, shortened. Decision (owner, 2026-10-26, after review pass 3, "amend two phrases"; the code stays): the passage after "…sends nothing then or when it is deleted." becomes: "A site that no longer shares usage data sees no feedback form and sends no feedback answer when the plugin is deleted. What else stops depends on what you switch off in the opt-out window: Freemius may still receive technical updates about the plugin's installation on the site, such as its version, the site address and whether the plugin is active, and any of the details above that you left on. If the plugin's menu shows an Account page and the site has no Pro license, Disconnect there deletes the record Freemius holds for the site." The Opt In or Opt Out link phrase and the short-version clause stay as decided after pass 2. Correction (pass 3): no name-and-email leak follows a "Communication" opt-out (the SDK skips its uninstall event for that site); the hook keeps the stored answer out of a registered opted-out site's deletion update and stops the name-and-email path for a site with no install record holding an answer from a pre-fix build.

## Boundaries & Constraints

**Always:** `vendor/freemius/` stays byte-identical to the 2.13.5 archive. Bug 90's behaviour for a skipped site and the snooze are unchanged; a site that shares usage data keeps the form. `docs/policies/privacy.md` changes first, then its published copy `postquality.com/privacy.md` and `docs/policies/readme-external-services.md` say the same. No text says deletion or deactivation deletes the Freemius record (only Disconnect does). The stored answer is removed only through the SDK's public `get_storage()` and only when the site does not share usage data now; a site that shares keeps its answer.

**Never:** patch the SDK; stop the SDK's technical install updates (the owner chose to describe them); touch any SDK storage key other than `uninstall_reason`; change the opt-in screen, the opt-out modal or Disconnect; add `uninstall.php` (WordPress would run it instead of the SDK's hook); edit the bug 90 ticket file.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Opted-out site deactivates | registered, tracking not allowed, not snoozed | filter answers false: no form, no reason stored | No error expected |
| Site sharing usage data | registered, tracking allowed, not snoozed | true: the form shows as before | No error expected |
| Sharing, snoozed | registered, tracking allowed, snoozed | false, as today | No error expected |
| Skipped site | not registered, tracking not allowed | false (bug 90 row unchanged) | No error expected |
| Licensed Pro site | registered, tracking allowed | true (the plan does not change the answer) | No error expected |
| Deletion, not sharing, answer stored | registered with tracking off, or not registered (a skipped site holding a pre-fix answer) | the stored answer is removed before the SDK's uninstall event: no reason, no name or email sent | No error expected |
| Deletion, sharing, answer stored | registered, tracking allowed | the answer is kept and goes with the deletion update, as the site agreed | No error expected |
